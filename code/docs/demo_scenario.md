# SIA 갈라 시연 시나리오 (구체화)

> 대상: 시각장애 아동 보행 보조 AI "시아" — 동물의 숲 컨셉 부스 체험
> 본 문서는 시연 시나리오 + 유저 플로우 + 데이터 흐름을 코드베이스 계약에 맞춰 정의한다.

---

## 1. 개요

| 항목 | 내용 |
|------|------|
| 컨셉 | 동물의 숲 마을에서 장애물을 피해 길 건너기 |
| 환경 | 가로·세로 3m 부스, 뒷벽에 동물의 숲 배경 스크린 |
| 사용자 | 체험자(아이 역할) — **이어폰**으로 시아의 음성을 들음 |
| 관람객/운영자 | **대시보드 모니터**로 시아가 보는 화면·대화·상태 확인 |
| 핵심 원칙 | **"시아야"로 부를 때만** 영상 분석(LLM) + 음성 응답(TTS). 위험 경고는 부르지 않아도 자동. |

---

## 2. 시스템 구성과 역할

```
┌──────────────┐   영상(MJPEG) + 초음파(cm)   ┌──────────────┐   WebSocket   ┌──────────────┐
│  ESP32-CAM   │ ───────────────────────────▶ │    서버       │ ◀───────────▶ │   대시보드     │
│  + 초음파센서  │                              │ (FastAPI+WS)  │   (이벤트/통지) │  (운영자 모니터) │
└──────────────┘                              └──────────────┘               └──────────────┘
       │                                             │
   사용자 착용                                   이어폰 ◀── 오디오 재생(서버측 스피커/BT)
```

- **디바이스(ESP32-CAM + 초음파)**: 실시간 영상과 정면 거리(cm)를 서버로 공급. 판단/분석은 하지 않음.
- **서버**: 영상·초음파 수신 → (1) 주기적 싼 인지(YOLO) (2) 사용자 "시아야" 요청 시 비싼 추론(LLM) (3) 위험 시 자율 경고(사전녹음).
- **대시보드**: 서버와 독립. 꺼져도 서버는 정상 동작. 운영자용 모니터 역할.

---

## 3. 단계별 유저 플로우

### 3-1. 착용 단계 (Stage 1: 대화/인트로)
1. 운영자가 대시보드에서 **세션 시작**(`new_session`).
2. 체험자 디바이스 착용, 이어폰 착용.
3. 체험자: "시아야 안녕?" → 시아: 인사 + **제품/부스 설명**(이어폰).
4. 운영자: 준비되면 **체험 시작**(`start_learning`, stage=3)로 전환.

> 이 단계는 영상 분석보다 **대화·온보딩** 중심. "시아야" 호출 시 일반 대화 응답.
> ※ stage 번호: 위험판단(`danger.judge`)이 **Stage 3에서만** 동작하므로 체험=Stage 3로 매핑한다(refactor_plan D1).

### 3-2. 체험 단계 (Stage 3: 온디맨드 VQA + 자율 위험)
1. 체험자가 장애물이 놓인 길을 건넌다.
2. 궁금할 때 **"시아야 ○○"** 라고 질문:
   - "시아야 앞에 뭐 있어?"
   - "시아야 방향 맞아?"
   - "시아야 지금 가도 돼?"
3. 시아: 현재 화면을 분석해 **2문장 이내**로 브리핑(이어폰).
4. **질문 횟수 카운팅** → 대시보드 표시(체험 지표).
5. (병행) 초음파가 위험 거리 이내면 → **부르지 않아도** "멈춰!" 자율 경고.
6. 운영자: 종료 시 **체험 중지**(`stop_learning`) → 세션 리셋.

> 호출어 없는 발화는 **무시**(LLM/TTS/채팅 모두 스킵).

## 4. 데이터 흐름 (3가지 경로)

### 경로 A — 사용자 질의응답 (온디맨드, LLM/TTS 사용)
```
마이크 → STT(텍스트)
        → "시아야" 포함? ── 아니오 ──▶ [무시] (브로드캐스트 없음)
              │ 예
              ▼
        호출어 제거 → 질문 추출
        → 현재 프레임 캡처(get_frame)
        → YOLO detect + enrich(+초음파)        # 싼 인지, 즉시
        → 장면 텍스트화(scene_to_korean)
        → LLM(VQA_PROMPT + 장면 + 히스토리 + 질문)  # 비싼 추론
        → TTS 생성/캐시 → 오디오 재생(이어폰)
        → 대시보드: user_stt → stt_response (채팅), 질문카운트+1
```

### 경로 B — 자율 위험 경고 (LLM 미사용, 사전녹음)
```
초음파(cm) < DANGER_DISTANCE_CM  또는  YOLO 근접 위험라벨
        → danger.judge() → {object, direction, audio_file}
        → 진행 중 자동묘사 취소(cancel_narration)
        → 사전녹음 .wav 즉시 재생(interrupt, PRIORITY_DANGER)
        → 대시보드: danger 통지(+카메라 오버레이)
```

### 경로 C — 실시간 인지 표시 (대시보드 전용)
```
영상 프레임 → YOLO(주기) → enrich
        → 0.25초마다 detections_update 브로드캐스트
        → 대시보드 카메라 오버레이/방향 패널 갱신   (LLM/TTS 없음)
```

## 5. 메시지·이벤트 계약 (현행 코드 기준)

### 서버 → 대시보드 (broadcast `type`)
| type | 의미 | 채팅 표시 |
|------|------|----------|
| `voice_listening` | 마이크 청취 중 | ✕ (상태) |
| `voice_processing` | STT 처리 중 | ✕ (상태) |
| `user_stt` | 사용자 질문(호출어 포함분만) | ✅ 오른쪽 |
| `stt_response` | 시아 답변 | ✅ 왼쪽 |
| `tts_start` / `tts_done` | 오디오 재생 시작/종료 | ✕ (상태) |
| `danger` | 위험 경고 | (오버레이/배지) |
| `detections_update` | 실시간 탐지 객체 | ✕ (오버레이) |
| `error` | 오류 안내 | (중앙 표시) |
| `ack` / `init_state` | 이벤트 확인/초기 상태 | ✕ |

> 채팅에는 **`user_stt`(STT)와 `stt_response`(TTS) 두 종류만** 남긴다.

### 대시보드 → 서버 (`event`)
| event | 동작 |
|-------|------|
| `start_learning` (stage) | 체험 시작, stage 설정 |
| `stop_learning` | 체험 중지 + 세션 리셋 |
| `new_session` | 새 세션(TTS 캐시 새로 시작) |
| `clear_tts_cache` | TTS 캐시 비우기 |
| `fallback` (audio_file) | 운영자 수동 음원 재생 |

## 6. 상태 모델 (AppState)

| 필드 | 의미 |
|------|------|
| `current_stage` | 1=착용/대화, 3=체험(위험판단 활성) |
| `learning_active` | 체험 진행 여부 |
| `session_id` | 현재 세션 ID |
| `question_count` *(신규)* | 체험 중 "시아야" 질문 누적 수 |

---

## 7. 실패·폴백 정책

| 상황 | 처리 |
|------|------|
| LLM 실패(429 등) | `error` 통지 + `buffer_01.wav` 재생 + 점진적 쿨다운(2→5→10→30초) |
| TTS 실패 | `error` 통지 후 **반드시 `tts_done`** (상태 복구) |
| 위험 음원 재생 실패 | `buffer_01.wav`로 대체 재생 |
| 호출어 미인식 | 무시(다음 발화 대기) + 운영자 수동 Fallback 패널 |
| 디바이스 영상 끊김 | 재연결 시도, 실패 시 `error` 통지 |

오디오 우선순위: **위험(0) > 대화(10) > 묘사(20) > 폴백(30)**.

---

## 8. 운영자 체크리스트 (시연 전)

1. `.wav` 폴백 음원 21종 생성 완료 (`audio/generate_fallback.py`).
2. `GET /preflight` — 음원·패키지·YOLO·node_modules·API키 OK.
3. ESP32-CAM 스트림 URL 연결 확인, 초음파 값 수신 확인.
4. 카메라 각도 15~30° 하향(뒷배경 스크린 객체 오인식 방지).
5. 이어폰/스피커 출력 점검, 대시보드 WebSocket 연결 확인.
6. 리허설: "시아야 앞에 뭐 있어?" → 2문장 응답 + 채팅 반영 확인.
