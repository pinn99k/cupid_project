# SIA 서버·통신 최적화 계획

> 작성 기준: 2026-06-05
> 목적: 갈라쇼 3분 시연에서 **끊김 없이** 동작하도록, 서버/통신 계층을 측정 기반으로 최적화한다.
> 전제: 시연 대본 = **Stage 3 + 실제 초음파 + 실제 ESP32-CAM 영상**, 대시보드 1개.

---

## 0. 핵심 원칙
1. **측정된 문제만 손댄다.** Phase 0 숫자 없이는 Phase 1 구현 없음.
2. 우선순위 기준은 **시연 가치 × 안전성** (난이도 아님).
3. 모든 변경은 **킬스위치(env) + 폴백**. 핫패스(영상/음성) 재작성은 플래그 뒤 + 리허설 후.

## 0-1. 현재 계측 상태 (근거)
- `utils/latency_logger.py`는 구현돼 있으나 **거의 안 쓰임**.
  - `main.py` 측정점 3개뿐: `detect_start`, `detect_end`, `danger_detected`.
  - `elapsed()` 집계가 main에서 호출되지 않아 **YOLO 추론 시간이 누적·저장되지 않음**.
  - **음성 경로(STT→LLM→TTS)는 계측 전무** — 정작 시연 "끊김"이 드러나는 곳.
  - `log()`이 호출마다 `print` → 핫루프 콘솔 스팸 + 소량 부하.
- 즉, **"무엇이 느린지" 데이터가 없다.** 이걸 먼저 만든다.

### 폐기된 후보 (이전 검토 결과)
- **detections_update 변화기반 송신**: `CameraView.jsx`가 bbox를 실시간 좌표로 그려 → 시그니처 스킵 시 **박스가 얼어붙는 시연 회귀**. 이득(대역폭) 미미. **폐기.**
- **WebSocket 하트비트**: 클라이언트가 이미 자동 재연결(1.5s) + 모르는 type 무시 → 3분 시연 가치 ≈ 0, 상시 태스크만 추가. **폐기.**
