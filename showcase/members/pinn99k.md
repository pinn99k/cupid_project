# 서버 · 대시보드 — @pinn99k

[← 프로젝트 소개로](../../README.md)

## 담당
- FastAPI + WebSocket 서버, React 모니터링 대시보드
- ESP32-CAM + 초음파 센서 펌웨어 (팀 공동)
- 음성 UX 개선 (호출어, STT, VAD, TTS, 되묻기)
- 비전 결과 안정화, 지연 계측, 테스트·설계 문서

## 해결한 문제

### 1. 오래 켜 둬도 안 죽는 실시간 서버
- **상황**: 탐지 루프(YOLO), 음성 루프(STT → LLM → TTS), 대시보드 통신이 한 서버에서 동시에 돕니다.
- **해결**: 카메라 프레임과 장면 결과를 락으로 보호한 "최신 1개" 슬롯에 담고, 읽을 때는 복사본을 넘겼습니다. 그래서 루프끼리 서로 기다리지 않습니다. 단계를 바꾸거나 세션을 리셋하면 이전 장면을 비워서, 지난 탐지 결과가 새 대답에 섞이지 않게 했습니다.
- **결과**: 부스 시연에서 서버를 끄지 않고 약 3시간 연속 운영했습니다.

### 2. 묻지 않아도 말하던 구조를 "물으면 답하는" 구조로
- **상황**: AI 루프가 탐지할 때마다 자동으로 장면을 묘사해서, 아이와의 대화와 TTS 재생 락·LLM API 할당량을 서로 빼앗았습니다.
- **해결**: 자동 묘사를 없앴습니다. AI 루프는 최신 탐지 결과를 장면 슬롯에 저장만 하고, 아이가 질문하면 YOLO를 다시 돌리지 않고 신선도 검사를 통과한 최신 장면으로 답하게 했습니다. 화면 대비 작은(먼) 물체는 관련성 게이트로 걸러 배경 화면 속 물체 오탐을 줄였습니다.
- 탐지 결과가 프레임마다 흔들리는 문제는 팀원이 최근 5프레임 다수결로 안정화했습니다.

### 3. 아이 말을 잘 알아듣는 음성 UX
- **호출어**: STT가 "시아야"를 "시야", "씨아", "sia" 등으로 적는 문제를 후보 목록으로 흡수했습니다. "러시아"처럼 단어 중간에 들어간 경우는 걸러냈습니다.
- **STT**: 로컬 faster-whisper 경로를 추가해 Google 음성인식과 설정으로 전환할 수 있게 했습니다. 부스 소음에 맞춘 적응형 VAD를 넣고, 침묵 판정 시간을 늘려 말끝이 잘리지 않게 했습니다.
- **되묻기**: 오류를 "목소리가 작음 / 인식 불가 / 호출만 함"으로 나눠 다르게 되물었습니다. 시스템 오류일 때 아이에게 "다시 말해줘"라고 잘못 묻지 않게 했습니다.
- **TTS**: 공급자 우선순위를 두고(기본 Edge-TTS), 캐시와 프리웜으로 첫 응답 지연을 줄였습니다. 문장 단위로 끊어 말하고 자막으로 표시했습니다.

### 4. ESP32-CAM 펌웨어 (팀 공동)
- 디바이스는 영상 스트리밍과 초음파 거리 측정만 하고, 판단은 모두 서버에서 하도록 역할을 나눴습니다.
- 서버와의 통신 규칙을 인터페이스 계약 문서로 정리하고, 팀원 교차검증 가이드를 작성했습니다.

### 5. 측정 기반 최적화
- 단계별 지연을 먼저 계측(집계·저장·로그 게이팅)하고, 그 수치를 보며 최적화했습니다.
- 디바이스 목업과 데모 시뮬레이터를 만들어, 하드웨어 없이 서버와 대시보드를 개발하고 테스트할 수 있게 했습니다.

## 배운 점
- 현장 시연은 기능보다 **끊기지 않는 것**이 먼저였습니다. 그래서 폴백 음원, 타임아웃, 쿨다운 같은 실패 경로를 먼저 설계했습니다.
- 다시 한다면 `print` 로그를 구조화된 logging으로 바꾸고, 하드웨어에 의존하는 테스트를 목업으로 분리해 CI에서 돌리겠습니다.

## 개발 방식
팀원과 폴더 단위로 담당을 나누고, 서버·대시보드 사이 통신 규칙은 인터페이스 계약 문서로 맞췄습니다. 구현에는 AI 페어 프로그래밍(Claude Code)을 활용했고, 설계 결정·검증·현장 테스트는 직접 했습니다.
